## 1. 운영 반영 체크리스트

순서대로 진행. 각 단계 전에 main·실서비스 영향 확인.

1. **DB 마이그레이션 (운영 DB)**
   - 이 브랜치에서 추가한 마이그레이션 3개. 전부 새 테이블·새 컬럼 추가만, 기존 데이터 변경 없음.
     | 파일 | 내용 |
     |---|---|
     | `drizzle/0005_vengeful_kree.sql` | WHOOP 테이블 3개 (whoop_connections / whoop_sleep / whoop_recovery) |
     | `drizzle/0006_early_malcolm_colcord.sql` | whoop_connections에 마지막 확인 시각·방식 컬럼 |
     | `drizzle/0007_access_logs.sql` | 접속 기록 테이블 + 수정·기간 전 삭제 금지 트리거 |
   - main에 같은 번호(0005~0007)가 이미 생겼다면 번호를 다시 생성해야 함.
   - 운영 DB의 `drizzle.__drizzle_migrations`에 0000~0004가 기록돼 있는지 먼저 확인.
   - ⚠️ `drizzle-kit push` 사용 금지. 운영 DB에는 코드에 정의 없는 테이블(shift_assessments / shift_events)이 있어서 지워질 수 있음. **WHOOP·접속 기록 테이블만 직접 추가.**
   - 0007을 머지와 같이 또는 먼저 적용. 늦으면 접속 기록이 조용히 저장 안 됨 (앱 동작은 정상).
2. **Vercel 환경변수 (Production)**
   | 이름 | 값 |
   |---|---|
   | `WHOOP_CLIENT_ID` | WHOOP 대시보드 앱 값 |
   | `WHOOP_CLIENT_SECRET` | 〃 |
   | `WHOOP_REDIRECT_URI` | `https://noctresearch.vercel.app/api/whoop/callback` |
   | `WHOOP_TOKEN_ENC_KEY` | **운영용으로 새로 생성** (32바이트 base64). 개발용 키 재사용 금지 |
   | `CRON_SECRET` | **현재 Vercel에 없음 → 새로 등록.** 없으면 자동 작업 주소 3개를 누구나 실행 가능 (코드는 값이 있으면 확인하도록 이미 구현) |
   | `COACH_EMAILS` | 코치 계정 목록 (운영 값 확인) |
3. **머지 → 배포**. `vercel.json` 자동 작업 3개 (시각은 UTC 기준)
   | 주소 | 주기 | 하는 일 |
   |---|---|---|
   | `/api/cron/whoop-refresh` | 매시간 | WHOOP 토큰 갱신 |
   | `/api/cron/whoop-sync` | 매일 03:00 UTC (= 12:00 KST) | 연결된 선수 최근 3일 다시 가져오기 |
   | `/api/cron/access-log-cleanup` | 매일 18:00 UTC (= 03:00 KST) | 보관 기간 지난 접속 기록 삭제 |
   - Vercel 요금제의 자동 작업 개수·주기 제한 확인.
   - 기존 `routine-check` 자동 작업, Slack 알림, Notion 설문 저장은 코드에서 삭제됨 → 배포하면 멈춤. 운영의 관련 환경변수는 배포 확인 후 정리.
4. **WHOOP 대시보드**
   - Webhook URL = `https://noctresearch.vercel.app/api/whoop/webhook` (v2). 지금은 테스트 서버 주소로 등록돼 있음 → 운영 주소로 교체.
   - 개인정보처리방침 URL을 운영 `/privacy` 주소로 교체.
5. **개인정보처리방침 시행일**: 테스트용으로 2026-10-22로 넣어 둠 → 운영 반영일로 변경 (`content/privacy-policy.md`).
6. **기존 선수 안내**: 배포하면 건강 정보 동의 기록이 없는 기존 선수에게 선수 앱 진입 시 동의 팝업이 뜸 (거부 시 로그아웃). 미리 안내 필요.
7. **실서비스 확인**: 연결 → 30일 백필 → 다음 날 웹훅 수신 → 코치 화면 "마지막 확인 · 자동" 표시 → 연결 해제.

## 2. 설계 문서와 달라진 점 / 추가 결정

| 항목 | 내용 | 이유 |
|---|---|---|
| WHOOP ID 타입 | `whoop_user_id`, `cycle_id`는 `bigint` | WHOOP가 int64 사용. int4면 넘칠 수 있음 |
| recovery 웹훅 id | recovery 웹훅의 `id`는 cycle id가 아니라 **수면 UUID** | WHOOP v2 실제 동작. 수면 조회 → 그 수면의 `cycle_id`로 회복 조회 |
| trace_id 테이블 없음 | 웹훅 중복 수신 기록 테이블을 만들지 않음 | 모든 처리가 "WHOOP에서 다시 가져와 덮어쓰기/삭제"라 같은 알림이 여러 번 와도 결과 동일 |
| 토큰 갱신 경합 | 웹훅과 cron이 동시에 토큰을 갱신해 한쪽이 거절되면, DB에 새 토큰이 저장됐는지 다시 확인 후 사용 | WHOOP refresh token은 1회용(rotating). 확인 없이 처리하면 정상 선수가 "재연결 필요"로 잘못 바뀜 |
| 테스트 환경 | **테스트 서버(Preview, feat/whoop) + 로컬 모두 테스트용 DB(Neon `dev-whoop`) + Clerk 개발 앱(`noct-dev`)** 사용. 운영 DB는 운영 반영 때만 | 처음엔 Preview가 운영 DB를 가리켜서 로컬만 썼음 → 10/19에 Preview(feat/whoop) 전용 환경변수로 분리 |
| WHOOP 수면 시작·끝 | `start`~`end` = **침대에 있던 시간**(누운 시각~일어난 시각). 잠든 시각이 아님 | 실제 데이터로 확인: end − start = 침대에 있던 시간, 침대 시간 = 깬 + 얕은 + 깊은 + REM + 미수신 (차이 0분) |
| 중복 연결 막기 | 같은 WHOOP 계정이 다른 앱 계정에 이미 연결돼 있으면 저장하지 않고 안내. WHOOP 쪽 연결은 끊지 않음 | 끊으면 기존 선수의 연결까지 끊어짐 |
| 정기·수동 동기화 | 매일 12:00 KST 자동 + 코치 "지금 동기화" 버튼 + "마지막 확인: 날짜 시각 · 자동/직접" 표시 (26시간 넘으면 빨간 경고) | 놓친 웹훅 복구 (WHOOP 권장) |
| 연결 상태 아이콘 | 코치 대시보드 선수 목록·선수 상세, 선수 내 정보·WHOOP 페이지 | 연결 여부를 한눈에 |
| 건강 정보 동의 | 가입 화면 필수 체크 + 동의 기록 없는 기존 선수에게 앱 진입 시 팝업 + 설문·준비자료 저장 시 서버에서 확인 | 개인정보처리방침 (민감정보 별도 동의) |
| WHOOP 연결 동의 | 연결하기 누르면 동의 시트. 동의 없으면 연결 불가 (서버에서도 차단) | 〃 |
| 만 14세 확인 | 가입 화면 "[필수] 만 14세 이상" 체크 + 확인 시각 기록 | 14세 미만은 부모 계정으로 이용 (Emma 결정) |
| 연결 해제 시 데이터 | 토큰 폐기 + 상태 `revoked`, 수집된 기록은 **코칭 종료까지 보관** | Emma 결정 |
| 코칭 종료 시 삭제 | 코치가 선수 상태를 "종료"로 바꾸면 [WHOOP 데이터 삭제] 버튼 (확인 창, 권한 해제 + 기록 삭제, 복구 불가) | 〃 |
| 회원 탈퇴 | 선수 내 정보 > 탈퇴: 본인 데이터 전체(WHOOP·기록·코칭 자료·파일·회원 정보) 삭제 후 Clerk 계정 삭제 | 개인정보처리방침 |
| 접속 기록 | `access_logs`. 코치·운영자(로그인 + 선수 데이터 조회·수정·삭제·다운로드) **2년** / 선수(로그인·WHOOP 연결·해제·탈퇴) **1년**. 수정·기간 전 삭제는 DB에서 차단, 기간 지난 기록은 매일 자동 삭제 | 안전성 확보조치 기준 제8조 + 방침 |
| 수면 기록 API | 로그인한 본인 기록만 조회·저장·수정·삭제 (비로그인 401) | 보안 보완 |
| 수면일지 미리 채우기 | 잠든·일어난 시각을 WHOOP 기록으로 미리 채움 (기상일 현지 시간대의 메인 수면, 15분 단위 반올림 + 원래 시각 안내, 선수가 고치면 안내 해제) | WHOOP 시작 = 누운 시각이라 그대로 쓰면 수면일지 "잠든 시각"과 다름 → 원래 시각 안내 |
| 선수 화면 데이터 비노출 | `lib/whoop/read.js`의 `SHOW_WHOOP_DATA_TO_ATHLETES = false` | 최종 UI 기획 전까지 선수에겐 연결/해제만, 데이터는 코치 패널에서만 |
| Slack·Notion 설문 제거 | Slack 알림, Notion 설문 저장, `routine-check` 자동 작업 삭제 | 사용하지 않기로 결정 (외부 전송은 AI 처리만 남음) |

## 3. 데이터 값 상태 정의 ('없음'과 '0' 구분)

수면·회복 각각, 날짜별로 아래 4가지 중 하나. (`lib/whoop/days.js`)

| 상태 | 뜻 | 값 |
|---|---|---|
| 기록 없음 | 그날 WHOOP 수면 기록 자체가 없음 (미착용 등) | 전부 null |
| 계산 중 | 기록은 있으나 WHOOP 점수 계산 전 (`PENDING_SCORE`) → 웹훅으로 자동 채워짐 | 전부 null |
| 계산 불가 | 잠은 감지됨(취침·기상 시각 있음), 측정 부족으로 WHOOP가 점수 산출 불가 (`UNSCORABLE`) | 점수류 전부 null |
| 값 있음 | 계산 완료 (`SCORED`) | 숫자. **0도 실제 측정값** |

- 빈 값(null)은 계산·표시 어디서도 0으로 바꾸지 않음 (예: 총 수면시간은 단계 하나라도 없으면 null).
- 차트는 최근 N일을 빠짐없이 표시. 기록 없는 날은 빈칸 + 선 끊김.
- 오늘 날짜는 기록이 있을 때만 표시 (아직 자는 중일 수 있으므로).

## 4. 알려진 한계

- **웹훅 응답 시간**: 로컬 측정 0.6~1.0초 (WHOOP 권장 "1초 이내"). 실서버가 오래 쉬다 깨어날 때는 더 걸릴 수 있음. 늦어서 실패해도 WHOOP 재전송(약 1시간 5회) + 매일 정기 동기화(최근 3일)로 복구. → 운영 후 Vercel 로그로 확인.
- **정기 동기화 범위**: 최근 3일만 다시 가져옴. 3일 넘게 자동 작업이 멈추면 그 사이 기록은 재연결 전까지 빠질 수 있음.
- **cycle(Strain)·운동 미저장**: WHOOP가 cycle 알림을 보내지 않음. 현재 cycle·workout은 저장하지 않음 (권한은 있음).
- **신체 정보(키·몸무게·최대 심박)**: `read:body_measurement` 권한을 요청하지 않음. 추가하면 기존 연결 선수는 재연결 필요.
- **WHOOP 테스트 등급(Sandbox)**: 최대 10명 연결. 그 이상은 WHOOP 심사(Build 등급) 필요.
- **연결 직후 대기 시간**: 연결 완료 화면이 30일 백필이 끝날 때까지 기다림. 실측 안 함.

## 5. 결정 대기 (Emma)

- **해외 선수 시간대 기준**: 현지 시각 vs 한국 시각 (수면일지 미리 채우기는 현재 현지 기준)
- **기존 선수 동의 팝업**: 운영 반영 시 안내 방법 + 동의 거부 시 처리 (환불 등)
- **탈퇴 후 코칭 자료 보관 여부**, 결제 기록 법정 보관 (앱 밖에서 관리?)
- **접속 기록 관련**: 코치 권한 부여·변경·회수 내역 3년 보관 방법, 점검 주기 (제8조②), 수면일지 수정·삭제 흔적 필요 여부
- **화면 표시 이름**: 상태값 "로그인" · "intake제출"을 화면에서만 알기 쉬운 이름으로 바꾸기 (DB 값은 유지)
- **코치 대시보드 [상세] 버튼**: 행 클릭과 같은 곳으로 가서 중복 → 삭제 또는 다른 기능
- **WHOOP 데이터 활용**: 수면 일관성 사용 여부, 주중/주말 비교 기준 (선수는 경기일·훈련일·휴식일이 더 의미 있을 수 있음)
- **최종 UI 기획**: WHOOP 브랜드 규칙 (출처 표시 "DATA BY WHOOP", 회복 점수 구간 색, 주요 점수 색 규정) 반영 → WHOOP 심사 전 필요

## 6. 운영 후 검토 후보 (부가기능)

설계 문서에 없던 것. 핵심 흐름 확인 후 필요하면 진행.

- **선수 동기화 버튼**: 선수가 아침에 직접 WHOOP 페이지를 보는 운영이라면 필요.
- **웹훅 먼저 응답하기**: 운영 로그에서 응답이 느리거나 실패가 보이면 적용 (정기 동기화가 있어서 적용 가능).
- **연결 직후 백필 뒤로 미루기**: 연결 대기 시간 실측 후 필요하면.
- **수면 기록 수정 시 저장값 불러오기**: 기존 기록 있는 날짜 선택 시 저장값 > WHOOP > 기본값 순서로 채우기.
