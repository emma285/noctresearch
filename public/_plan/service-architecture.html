Service Architecture

코치와 선수가
한 시스템 안에서 움직이는
수면코칭 서비스

지금은 코칭 노트를 따로 만들어 붙이고, 상태가 여기저기 흩어져 있어요. 이 문서는 선수·코치가 각자 앱에서 자연스럽게 일하고, 데이터가 마스터 하나로 흐르는 구조를 UX와 DB 양쪽으로 그린 설계안이에요.

2026 · 운동선수 수면코칭 (프로골퍼 1호 윤이나 기준)
TL;DR
한 줄로 바뀌는 것 3가지
1
데이터는 마스터 하나로선수 상태·세션·리포트·기록이 전부 Notion 마스터에서 나오고, 앱은 그걸 읽기만 해요. (Clerk은 로그인만)
2
코치는 앱 안에서 일해요세션 노트를 로컬 문서로 따로 쓰고 "붙여줘"가 아니라, 코치 콘솔에서 바로 작성 → 자동으로 세션·리포트·선수 포털에 흘러요.
3
선수는 자기 여정만 봐요내 진행 단계·다음 세션·리포트 아카이브만 깔끔하게. 코치용 SOAP 노트 같은 건 안 보여요.
As-is
지금 구조의 문제
돌아가긴 하는데, 손이 많이 가고 데이터가 흩어져 있어요.

✕세션 노트를 따로 만들어 첨부

코치가 SOAP 노트를 로컬 md로 쓰고, 개발자(=나)한테 "이거 앱에 붙여줘"라고 넘겨요. 매 세션마다 수작업 + 사람 개입이 필요해요.

→ To-be 코치 콘솔에서 노트 작성 → 세션 DB에 바로 저장.

✕상태가 세 군데에 흩어짐

여정 상태는 Clerk 메타데이터, 날짜·문구는 코드에 하드코딩, 실제 데이터는 DB. 같은 사실이 여러 곳에 있어 어긋나기 쉬워요.

→ To-be 마스터 `상태`·`다음 세션`이 유일한 진실. (이미 이관 시작함)

✕리포트가 코드에 박혀 있음

리포트 제목·날짜·설명이 코드(레지스트리)에 하드코딩. 새 리포트/새 선수마다 개발자가 코드를 고쳐야 해요.

→ To-be 리포트 DB에서 관리, 코치가 발행·공개.

✕마스터에 1명만 등록

지금은 윤이나만 마스터에 있고, 나머지는 옛 경로(Clerk)로 돎. 선수가 늘면 수동 등록/불일치 위험.

→ To-be 가입·초대 시 마스터 행 자동 생성(백필 + upsert).
Principles
설계 원칙 5
1
단일 소스(Single Source)모든 사실은 마스터(+하위 DB)에 한 번만 저장. 앱·리포트·포털은 거기서 읽는다.
2
코치는 도구 안에서 일한다노트·리포트·스케줄을 앱에서 만들고, 그 행위가 곧 데이터가 된다. 사후 수작업 없음.
3
선수는 필요한 것만 본다내 여정·다음 세션·리포트. 코치 내부 노트/개념화는 비공개.
4
계정과 데이터를 분리Clerk = 로그인(신원)만. 코칭 데이터는 마스터. 이메일로 연결.
5
자동으로 흐르게세션 저장 → 다음세션·주차 갱신, 리포트 발행 → 아카이브 노출. 상태 전이는 이벤트로.

Single Source of Truth
Notion 마스터 + 하위 DB

코칭 클라이언트(마스터)를 중심으로 intake·세션·리포트·기록·인터벤션이 relation으로 연결. 두 앱은 이 데이터를 읽고 쓴다. 로그인만 Clerk.

Client UX
선수 여정 — 화면 흐름
선수는 각 단계에서 "지금 할 일"과 "쌓인 결과"만 본다.
1 · 초대
코치가 선수를 등록
코치 콘솔에서 이름·이메일·종목·티어 입력 → 마스터 행 생성(상태: 초대됨).
선수 화면: 초대 링크 수신 → 로그인 안내
2 · 로그인
한 계정으로 로그인
이메일로 가입/로그인(Clerk). 이메일이 마스터와 매칭되며 상태: 로그인.
선수 화면: 포털 진입 · "사전 질문지 작성" 하나만 활성
3 · 진단
사전 수면 질문지
68문항 제출 → intake DB 저장 + 마스터 상태: intake제출.
선수 화면: 여정 1단계 완료 · 첫 세션 준비 안내
4 · 첫 리포트
코치가 첫 리포트 발행
코치가 진단 기반 리포트를 만들고 공개 → 리포트 DB + 마스터 공개 리포트.
선수 화면: 리포트 아카이브에 1차 리포트 오픈
5 · 세션 (반복)
1:1 코칭 세션 진행
세션마다 코치가 앱에서 노트 작성 → 세션 DB. 회차·다음세션 자동 갱신. 상태: 진행중.
선수 화면: 진행 N회차 · 다음 세션 일정 (미정이면 "조율 중")
6 · 기록
매일 수면 로그 + 워치
30초 로그·루틴 체크·워치 캡처 업로드 → 기록/주간 데이터 DB. (로그 앱 = PWA 홈화면)
선수 화면: 루틴 타임라인 · 오늘 기록
7 · 점검
주기적 점검 리포트
코치가 기록 기반 점검 리포트를 발행 → 아카이브에 차곡차곡.
선수 화면: 아카이브에 리포트 누적 (최신순)
목표
흔들리지 않는 회복 루틴
세션마다 목표를 다듬고, 성취가 포털에 쌓인다.
Coach UX
코치 콘솔 — 한 선수를 끝까지
핵심은 "세션 노트를 앱에서 바로 쓴다"예요.

① 선수 목록

내 담당 선수들. 각 카드에 상태·다음 세션·마지막 기록·미확인 표시. 눌러서 상세로.

② 선수 상세 — 개요

intake 요약, 종목·티어, 진행 회차, 다음 세션, 최근 로그·워치. 한 화면에서 이 선수 상태를 파악.

③ 세션 노트 작성 핵심

세션 후 코치가 이 화면에서 SOAP 노트를 바로 입력(주관/객관/평가/계획 + 다룬 토픽·인터벤션). 저장하면 세션 DB에 회차로 쌓이고, 마스터 회차·다음 세션이 갱신돼요. 로컬 md·수동 첨부 없음.

④ 리포트 발행·공개

리포트를 만들고(또는 연결) 선수에게 공개 토글. 리포트 DB + 마스터 공개 리포트에 반영 → 선수 아카이브에 자동 노출.

⑤ 다음 세션 배정

다음 세션 날짜를 잡으면 마스터 다음 세션 갱신 → 선수 포털 D-day/일정에 즉시 반영. 미정이면 "조율 중".

Key Flow
세션 → 노트 → 리포트 → 포털

Roadmap
어디까지 왔고, 뭐가 남았나
완료마스터 읽기 배선
  • 상태·다음세션·회차·이름을 마스터에서 읽어 포털 렌더
  • 진행중 뷰(N회차·조율 중) + 리포트 아카이브(지수 미러)
  • 리포트 공개상태 마스터 이관 + 코치 토글이 마스터도 기록
  • 프로덕션 배포됨(윤이나 라이브)
다음코치가 앱에서 일하게
  • 세션 노트 작성 UI(코치 콘솔) → 세션 DB 저장 · 회차/다음세션 자동 갱신
  • 리포트 DB 신설 → 카탈로그·발행·공개를 코드에서 DB로
  • 코치 상세에 세션 노트 열람(선수엔 비공개)
  • 남은 쓰기 경로(intake·prep·log·배정)를 마스터 상태 전이로
나중확장·자동화
  • 선수 백필 + 가입 시 마스터 자동 생성(upsert)
  • 로그 PWA(홈화면 설치·세션 유지)로 매일 기록 정착
  • 주간 데이터 자동 집계 → 점검 리포트 반자동
  • 프로그램 길이 등 잔여 필드 마스터화, Clerk 메타 폐기
