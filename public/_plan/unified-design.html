02 · Entry Flow

상태 기반 첫 화면 (모바일 + PC)

로그는 첫 세션 이후에야 의미가 생겨요. 그래서 입구가 아니라 상태로 첫 화면을 정합니다. 세션 끝나고 코치가 켜주는 logActive 플래그 하나로 갈라져요.

진입 /도메인·홈아이콘
→
로그인 확인Clerk 세션
→
logActive?첫 세션 완료 플래그
CASE A · 첫 세션 전 (logActive = false)
아직 로그 쓸 게 없음 → 포털로
PC 포털 (여정·온보딩) /portal
모바일 포털 (여정·온보딩) /portal
CASE B · 첫 세션 후 (logActive = true)
기기에 따라 첫 화면이 갈림
PC 포털이 디폴트 (넓은 화면=관리) /portal
모바일 로그가 디폴트 (매일 기록) /log
🏠 홈아이콘(PWA)은 첫 세션 후에 설치 안내 → manifest start_url = /log 로 박아두면, 데일리 유저는 아이콘 탭 = 무조건 로그부터. 코드 분기 없이 OS가 처리해줘요.
// 미들웨어 or / 라우트 — 지금은 무조건 /portal redirect 중 if (!user) → /sign-in else if (!logActive) → /portal // CASE A: 양쪽 다 포털 else if (isMobile) → /log // CASE B 모바일: 로그 else → /portal // CASE B PC: 포털
🔑 logActive = 마스터 DB(클라이언트)의 필드 하나. 세션 끝나고 Emma가 “이제 매일 기록해요” 할 때 켜짐. MASTER_DONE_STATES 에 “온보딩완료” 넣는 식으로 이미 있는 상태값에 얹으면 돼요.
