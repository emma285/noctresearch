# 리포트 엔진

모든 수면 코칭 리포트(intake·정기)를 **사람별 하드코딩 없이** 자동 생성한다.
사람별로 손대는 파일은 `reports/<name>/`의 config·narrative·overlay 뿐. 숫자·차트·톤·디자인은 엔진이 강제한다.

## 파이프라인 (새 리포트는 반드시 스캐폴드부터 = 표준 자동 적용)

```
node scaffold.mjs <name> <email> <start> <end> "이름 님" "N차 리포트"   # 0) 표준 템플릿에서 생성
DBURL=<Neon> node extract.mjs reports/<name>/config.json               # 1) Neon logs → snapshot.json (동결)
# 2) reports/<name>/의 __…__ 자리표시자를 그 사람 데이터·코치 해석으로 채움 (숫자=실측, 인용=세션/일지)
bash publish.sh reports/<name>/config.json                             # 3) render → 린트 → 감사 → 인용검증 (4단 게이트)
```

**엔진 = 템플릿.** 레이아웃·컴포넌트·컬러·위계·게이트는 전부 공통(`render.py`+`theme.css`+lint/audit/verify)이라 새 리포트에 자동 적용된다. 사람마다 다른 건 `reports/<name>/`의 데이터(snapshot·overlay)와 해석(narrative·redesign·claims)뿐. `template/`에 표준 skeleton(섹션 순서·지표 정의)이 있어 스캐폴드가 그걸 복제한다.

## 컴포넌트/디자인 표준 (2026-09-09 확정, 이지수 3차에서 도출)
- **히어로(네이비)**: 회차 메인 타이틀 + KPI 지표(기록일수·총수면 중앙값·입면율·각성 없는 날)
- **섹션 제목 = H2(20px 네이비)** 전부 통일(.sh/.shead h2 동일). 서브라벨(.subhead/.tcap)만 작게(인디고)
- **핵심 지표(Stat)**: 값 + **변화량(delta, 색 텍스트 ↑↓)** + **상태 배지(알약)** — delta와 배지 형태로 구분. delta는 직전 기간을 같은 방식으로 재계산
- **상세 지표 공통 문법**: 헤더(제목+배지+`기준 :`) → **Period Comparison**(시기별 행, 세그먼트 색 없음, 값 우선, 3일 이하=`참고 데이터` 배지) → 보조지표(있을 때, 강도 낮게) → **코치 해석**(콜아웃). 큰 컬러막대·큰 그린배너 금지
- **분포(산점도)**: 흰 배경+테두리 차트(코치 해석 틴트 카드와 구분), 점 중립색·주목 구간만 브랜드 틴트
- **요인**: 도움/방해 칩(색은 칩만), **코치 소견**: 저강도 콜아웃, **앞으로의 목표**: 측정가능 목표 카드
- **컬러 = 의미**: 그린=양호/개선·앰버=주의·코랄=방해, 인디고=브랜드. 라벨/구간은 중립. 팔레트 밖 색(틸 등) 금지
- **표기**: 시간=6시간 30분/편차=1시간 17분(분 단위도 시간분)·기간(구간X)·수면 중 각성(밤중X)·평균 각성 0.6회(소수 허용)

`publish.sh` = 발행 게이트. 셋 다 통과해야 report.html 발행:
1. **render.py** — snapshot+config+narrative+theme.css → report.html. 대표값=중앙값+IQR, 차트는 config.segments 기반, prose는 narrative 슬롯에서만.
2. **lint.mjs** — 톤·디자인 린트. AI티·어색표현·금지표기(소수점 시간/박/em dash/화살표/격식혼용/밤중…)와 타일 그리드 orphan을 스캔. **FAIL 0이어야 통과.**
3. **audit-report.mjs**(../report-audit) — 데이터↔해석 정합. 숫자 재계산·특이일 원인이 그날 원본에서 성립하는지. **FAIL 0이어야 통과.**

## 왜 코드 게이트인가
메모리·문서(톤 룰, 디자인 가이드)는 **회상**일 뿐 매번 자동 실행되지 않는다. 감사·린트를 **코드로 박아** 발행 때마다 강제한다. 룰이 늘면 `lint.mjs`의 TONE/DESIGN 배열에 추가.

## reports/<name>/ 파일
| 파일 | 손작업? | 내용 |
|---|---|---|
| `config.json` | ✍️ | 유저·기간·구간(segments)·섹션순서·회차 |
| `overlay.json` | ✍️ | 사람이 그날 메모 읽은 검증 해석값(cpap 등). 자동 파생보다 우선 |
| `narrative.json` | ✍️ | 해석 문장 슬롯(src 태그). 데이터 문장은 엔진이 자동 |
| `snapshot.json` | 🤖 | extract 생성(동결 원본) |
| `claims.json` | ✍️ | 감사용 근거(날짜·기대값) |
| `report.html` | 🤖 | render 생성물 |

## N차 리포트 표준 틀 (2026-09-08 확정)
여정 서사: 어디서 시작 → 뭘 시도 → 뭐가 통함 → 지금 상태(기준 대비) → 얼마나 나아짐 → 다음.
섹션 순서(config.sections로 on/off):
1. 표지(hero) · 2. 핵심 지표 KPI(각 기준/강점 라벨) · 3. 종합 소견(BLUF: 현황+좋아진 점/주의할 점)
4. 지표 상세(규칙성·각성·총수면 등 — 제목+배지+**기준(baseline)**+차트+소견)
5. 변화 추세(핵심 지표 1개 시간축 = 비포애프터, N≥2)
6. 생활 요인(음주 비교·양압기·낮잠 등)
7·8. **도움이 된 것·안 된 것**(항목→효과, 각 일지날짜·세션차수 근거). ※ 2026-09-08 Emma: 7·8은 **항상 하나로 합침**(시도 인벤토리와 효과가 겹침). "안 된 것"엔 **하기로 하고 안 지킨 것**만(원래 안 하던 건 제외). 코치 해석·추측 금지(예: "졸릴 때 눕기→8시간"은 근거 약해 삭제)
9. 시작 시점 대비(선택, N≥2 · 첫 기록 스냅샷)
10. 전문의와 확인할 것(의료 연계, 있을 때) · 11. 다음 목표(세션 액션아이템) · 12. 면책·출처

**N차별 적응**: 1차(인테이크)=2·3·4·10·11만(이력 없어 5·7·8·9 생략). 2차+(경과·로그)=전체.
**7·8은 근거 필수** — 각 항목 `{내용,효과,근거(일지날짜│세션차수)}` → verify-citations 자동 대조, 근거 없으면 발행 불가.

## 워딩 표준 (3차에서 확정, lint 강제)
기간(구간 X) · 수면 중 각성(밤중 X) · 시간=6시간 30분(소수점 X) · N일(N박 X) · 영어 보조타이틀 X · 보라 영역라벨 X · em대시/화살표 X · 모든 지표에 기준(baseline) · 친근체(~해요/~예요) · 날짜 목록은 .drow 정렬표 · 데이터 의인화("출렁/벌어졌") X.

## 표준 룰
- 원천 = 슬립로그 + 루틴로그 + 세션기록 + 로그메모 전부 (Neon `logs` kind=sleep|routine, `sessions`)
- 대표값 = 중앙값 + 편차(IQR). 평균 금지(수면데이터는 치우침·극단값 많음)
- 톤 = 친근체(~해요/~예요) 통일. em dash·화살표·소수점 시간·박 금지. "수면 중 각성"(밤중 X)
- 섹션 = 3단 제목(영역라벨→지표 명사형→배지). 뼈대 고정, 지표섹션은 데이터 주제로 교체
- alcohol 매핑 = 같은 날 · cpap = 그날 메모에서만(overlay)
